# M4.4 Persistent Conversation Memory

## Architecture
Rural MediBot implements a robust, privacy-first Persistent Conversation Memory model mapped explicitly via PostgreSQL (`conversations`, `messages`, `patient_contexts`) integrating tightly with LangGraph execution state. 

### Conversation Lifecycle
1. **Creation**: When an authenticated user submits a chat message without a `conversation_id`, a new `Conversation` row is initialized (Status: `active`).
2. **Continuation**: Future messages passing the `conversation_id` append to the `messages` table.
3. **Retrieval**: Authorized clients retrieve histories through `/api/conversations/{id}`.

### Message Storage
- Stores the `role` (user/assistant).
- Stores the exact `content`.
- Metadata JSON holds strict safety tracking: `risk_level`, `is_emergency`, `triage` properties, and `language`.
- Does NOT store audio streams or credentials.

### Patient Context
A minimal structured memory schema (`PatientContext`) ensures medical context is isolated from raw text extraction errors. Includes `known_conditions`, `allergies`, and `current_medications`.
Crucially, it is explicitly populated by the patient or medical staff, avoiding potentially hallucinatory automated AI profiling.

### Ownership & Data Isolation (RBAC)
- All conversation APIs extract the user identifier directly from the verified JWT `sub` via `Depends(get_current_active_user)`.
- IDOR attempts return explicit 404s, avoiding existence leaks.

### Emergency Safety Ordering (M4.2 Preservation)
The workflow strictly executes:
`USER INPUT -> M4.2 DETERMINISTIC TRIAGE -> MEMORY OVERRIDE CHECK`
Memory **never** downgrades a deterministic emergency trigger (e.g. if the user says "I am fine" initially but later writes "I can't breathe", RED triage correctly aborts LangGraph contextual retrieval instantly).

### Memory Windows
LangGraph agent state fetches a bounded context window:
- Bounded Patient Context (summarized string)
- Reverse chronological limit of 10 recent historical messages

### Multilingual Storage
Messages persist inherently as written. `language` is saved in metadata for precise TTS translation and context continuation in the user's preferred language natively without destructive overwriting translation.
